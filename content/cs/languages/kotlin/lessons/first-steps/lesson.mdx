<Section id="motivation" kind="motivation" title="Why Kotlin">

Open an Android app made in the last few years, look at its source, and it will very likely be Kotlin. Look inside the back end of a bank or an online marketplace, and you may find Kotlin there too, running on the same Java Virtual Machine as the Java code next to it. Open a Gradle build file in almost any modern Java project, and the `build.gradle.kts` you see is Kotlin as well.

Kotlin is a statically typed language made by **JetBrains**, the company behind the IntelliJ IDEA development environment. It was designed by people who wrote a great deal of Java and wanted a language that kept everything good about the Java platform (its virtual machine, its libraries, its tools) while removing the friction they met every day. The result is a language with a few clear priorities:

- **Conciseness without cleverness.** A data class with equality, hashing and a readable `toString` is one line. Types are usually inferred. But Kotlin avoids terse symbols and magic; code reads like what it does.
- **Safety, especially from null.** In Kotlin a `String` can never be `null`; a value that might be missing has a different type, `String?`, and the compiler makes you handle the missing case. The most common crash in Java programs, the `NullPointerException`, becomes rare.
- **Interoperability.** Kotlin calls Java and Java calls Kotlin, in the same project, with no wrappers. Any Java library is a Kotlin library.
- **Pragmatism.** Features earn their place by solving real problems in real codebases, and the tooling (the compiler, IntelliJ IDEA, Android Studio, Gradle) is first-class.

Today Kotlin is used in three main places: **Android**, where Google has recommended it as the preferred language since 2019; **server-side** development, with frameworks such as Spring and Ktor; and **Kotlin Multiplatform**, which shares code (business logic, networking, sometimes user interfaces) between Android, iOS, desktop and the web.

</Section>

<Section id="history" kind="history" title="A short history">

JetBrains began working on Kotlin around 2010 in its Saint Petersburg office, with Andrey Breslav as lead designer, and announced it publicly in **July 2011**. The name comes from Kotlin Island, near Saint Petersburg, an echo of Java being named after an island too. The language was developed in the open, and version **1.0** shipped in February 2016 with a promise of backward compatibility.

The turning point came in 2017, when Google announced official support for Kotlin on Android; in 2019 Google declared Android development "Kotlin-first". The Kotlin Foundation was created by JetBrains and Google to steward the language. Coroutines, Kotlin's approach to asynchronous programming, became stable in 2018. Kotlin Multiplatform was declared stable in late 2023.

**Kotlin 2.0**, released in 2024, replaced the compiler's front end with a new one, called **K2**, that is faster and the foundation for future language features. The 2.x releases since then have added features such as guard conditions in `when`, non-local `break` and `continue`, and multi-dollar string interpolation. JetBrains ships a language release about every six months with smaller tooling releases in between. This course uses Kotlin 2.4, and every program in it was compiled with the Kotlin 2.4.21 compiler and run on JDK 21.

</Section>

<Section id="intuition" kind="intuition" title="One language, several targets">

Kotlin is a language, not a runtime. Its compiler has several back ends:

- **Kotlin/JVM** produces Java bytecode, exactly the kind of `.class` files `javac` produces. The JVM cannot tell Kotlin code from Java code. This is the target used in this course, on Android, and on servers.
- **Kotlin/Native** produces machine code (via LLVM) for iOS, macOS, Linux and Windows, with no JVM at all.
- **Kotlin/JS** and **Kotlin/Wasm** produce JavaScript and WebAssembly for browsers.

Kotlin Multiplatform builds on these: you write shared code once, in a "common" module that may use only the Kotlin standard library and multiplatform libraries, and platform-specific code where you need it.

On the JVM, Kotlin adds one small thing to your program: the **Kotlin standard library**, a JAR with functions such as `println`, `listOf` and `maxBy`. Everything else comes from the JVM and from Java's own library, which Kotlin uses directly. That is why a Kotlin program can call `java.time.LocalDate` without any adapter, and why a team can add Kotlin to an existing Java codebase one file at a time.

</Section>

<Section id="install" kind="computation" title="Installing and running Kotlin">

There are several good ways to get started:

- **No installation.** The [Kotlin Playground](https://play.kotlinlang.org/) runs Kotlin in your browser. It is ideal for the short programs in the first lessons.
- **IntelliJ IDEA or Android Studio.** Both include Kotlin support. Create a new Kotlin project and the IDE sets up Gradle and a JDK for you. This is how most professionals work.
- **The command-line compiler.** Download `kotlinc` from the [Kotlin releases on GitHub](https://github.com/JetBrains/kotlin/releases), or install it with a package manager such as SDKMAN! (`sdk install kotlin`) or Homebrew. You also need a JDK (version 17 or newer is a good choice; this course used JDK 21), because the compiler runs on the JVM and so do its programs.

With the command-line tools, a program goes from source to running in two steps:

```bash
kotlinc main.kt -include-runtime -d main.jar   # compile, bundling the Kotlin standard library
java -jar main.jar                             # run it on the JVM
```

`-include-runtime` puts the standard library inside the JAR so that plain `java -jar` can run it. Checking the version is `kotlinc -version`; on the machine this course was tested on, it printed `info: kotlinc-jvm 2.4.21 (JRE 21.0.13.1+2-LTS)`. In real projects you will rarely call `kotlinc` yourself: Gradle (or Maven) does it, as you will see in <LessonLink slug="java-interop-and-tooling">Java interoperability, Gradle and testing</LessonLink>.

</Section>

<Section id="first-program" kind="examples" title="A first program">

```kotlin check
fun main() {
    println("Hello, Kotlin!")
    val firstYear = 2011
    val stable = 2016
    println("Announced in $firstYear, version 1.0 in $stable: ${stable - firstYear} years later.")
    println("This program runs on Kotlin ${KotlinVersion.CURRENT}.")
}
```

```text
Hello, Kotlin!
Announced in 2011, version 1.0 in 2016: 5 years later.
This program runs on Kotlin 2.4.21.
```

Compared with Java, notice what is *not* there:

- **No class.** `fun main()` is a **top-level function**: Kotlin does not require code to live inside a class. (The compiler still puts it in a class, named after the file: `main.kt` becomes the class `MainKt`, because the JVM needs one.)
- **No semicolons.** A line break ends a statement. Semicolons are allowed but almost never written.
- **No types on the variables.** `val firstYear = 2011` declares a read-only variable whose type, `Int`, the compiler **infers** from the value. It is still statically typed: try to assign a string to it later and the program will not compile.
- **String templates.** Inside a string, `$firstYear` inserts a variable's value, and `${stable - firstYear}` inserts the value of any expression.

`println` is a function from the Kotlin standard library. `KotlinVersion.CURRENT` describes the version of the standard library the program is running with.

#### A program with a function and a loop

```kotlin check
fun greeting(city: String, hour: Int): String {
    val part = if (hour < 12) "morning" else if (hour < 18) "afternoon" else "evening"
    return "Good $part, $city!"
}

fun main() {
    val cities = listOf("Lagos", "Lima", "Hanoi", "Kuala Lumpur")
    val hours = listOf(8, 13, 19, 23)
    for ((city, hour) in cities.zip(hours)) {
        println(greeting(city, hour))
    }
    println("${cities.size} greetings; the longest city name is ${cities.maxBy { it.length }}.")
}
```

```text
Good morning, Lagos!
Good afternoon, Lima!
Good evening, Hanoi!
Good evening, Kuala Lumpur!
4 greetings; the longest city name is Kuala Lumpur.
```

Reading it line by line:

- `fun greeting(city: String, hour: Int): String` declares a function. Parameters are written *name: Type*, and the return type comes after the parentheses. Kotlin puts the name first and the type second everywhere, which reads naturally ("city, a string") and makes the type easy to leave out where it can be inferred.
- `if` is an **expression**: it produces a value, so `val part = if (...) "morning" else ...` needs no separate conditional operator. Kotlin has no `c ? a : b` conditional operator; it does not need one.
- `listOf(...)` creates a read-only list. `cities.zip(hours)` pairs the two lists element by element, and `for ((city, hour) in ...)` takes each pair apart into two variables (**destructuring**).
- `cities.maxBy { it.length }` passes a **lambda** (the code in braces) to `maxBy`. A lambda with one parameter can refer to it as `it`. You will write lambdas constantly in Kotlin; <LessonLink slug="control-flow-and-functions">Control flow, when and functions</LessonLink> explains them properly.

</Section>

<Section id="interop" kind="examples" title="Java's library, from Kotlin">

Because Kotlin/JVM compiles to the same bytecode as Java, the whole Java standard library is available, with some conveniences:

```kotlin check
import java.time.LocalDate
import java.time.temporal.ChronoUnit

fun main() {
    // Java's standard library, used directly from Kotlin
    val today = LocalDate.of(2026, 11, 19)
    val newYear = LocalDate.of(2027, 1, 1)
    println("$today is a ${today.dayOfWeek}")               // getDayOfWeek() becomes a property
    println("${ChronoUnit.DAYS.between(today, newYear)} days until $newYear")

    val names = java.util.ArrayList<String>()                // a Java collection class
    names.add("Ada")
    names.add("Grace")
    println(names.joinToString(" & "))                     // a Kotlin function on a Java object
}
```

```text
2026-11-19 is a THURSDAY
43 days until 2027-01-01
Ada & Grace
```

Java's `getDayOfWeek()` method appears in Kotlin as the property `dayOfWeek`: Kotlin treats Java getters and setters as properties. There is no `new` keyword; you create an object by calling its constructor like a function. And Kotlin's own functions, such as `joinToString`, work on Java's collection classes, because Kotlin's collections *are* Java's collections underneath, viewed through Kotlin interfaces.

#### A compiler error

`val` means the variable cannot be reassigned. This program tries anyway:

```kotlin
fun main() {
    val count = 1
    count = 2
    println(count)
}
```

and `kotlinc` refuses it:

```text
E.kt:3:5: error: 'val' cannot be reassigned.
    count = 2
    ^^^^^
```

The message gives the file, the line and column (3:5), a description, and the offending code underlined. Use `var` for a variable that genuinely needs to change, but prefer `val`: code where most names never change is far easier to follow, and Kotlin style guides recommend `val` by default.

</Section>

<Section id="side-by-side" kind="human" title="Kotlin and Java at a glance">

If you already know some Java, this table maps the most common constructs. If you do not, skip it; every row is taught properly in the lessons that follow.

| Idea | Java | Kotlin |
| --- | --- | --- |
| Read-only variable | `final String name = "Ada";` | `val name = "Ada"` |
| Mutable variable | `int count = 0;` | `var count = 0` |
| Function | `static int twice(int x) { return 2 * x; }` | `fun twice(x: Int) = 2 * x` |
| String building | `"Hi " + name + "!"` | `"Hi $name!"` |
| Conditional value | `x > 0 ? "pos" : "neg"` | `if (x > 0) "pos" else "neg"` |
| Possibly missing value | any reference may be `null` | only `String?` may be null |
| Data holder | a record or a class with equals, hashCode, toString | `data class Point(val x: Int, val y: Int)` |
| Creating an object | `new StringBuilder()` | `StringBuilder()` |
| Inheritance | classes open unless `final` | classes final unless `open` |

Two habits will serve you from the first day. Let the compiler infer types for local variables, but write them on public functions, where they document the contract. And read the warnings IntelliJ IDEA or the compiler gives you: Kotlin's tools are good at suggesting the idiomatic form of what you wrote, and following those suggestions is one of the fastest ways to learn the language's style.

</Section>

<Section id="misconceptions" kind="misconceptions" title="Common misconceptions">

<Misconception>

**"Kotlin is only for Android."** Android made Kotlin famous, but it is widely used on servers (Spring has first-class Kotlin support, and Ktor is a Kotlin-native framework), in build scripts, and in multiplatform apps that share code with iOS.

</Misconception>

<Misconception>

**"Kotlin replaces Java, so I do not need to know anything about Java."** On the JVM, Kotlin runs on Java's virtual machine and uses Java's libraries. Stack traces, profilers, the garbage collector and most libraries you meet are Java's. Kotlin developers who understand the platform underneath debug much faster.

</Misconception>

<Misconception>

**"Kotlin is slower than Java because it adds a layer."** There is no interpreting layer: Kotlin compiles to ordinary bytecode, and the JVM's JIT compiles it like any other. Some Kotlin features (lambdas passed to `inline` functions, for example) can even produce leaner bytecode than the equivalent Java.

</Misconception>

<Misconception>

**"`val` makes an object immutable."** It makes the *variable* read-only. <code>val names = java.util.ArrayList&lt;String&gt;()</code> cannot be pointed at another list, but the list itself can still change, as the interop example shows.

</Misconception>
